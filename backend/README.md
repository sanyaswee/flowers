# Backend Server
The server for handling data and controlling the nodes.

## HTTP Documentation (Swagger / openapi)
The documentation is available on [localhost:3000/docs](localhost:3000/docs)

### Note
The documentation was automatically generated by [utoipa](https://github.com/juhaku/utoipa), based on comments, structs and datatypes, thats why the values in example responses may be weird

## Running the server

### Debian/Ubuntu (TODO)

First of all, install the dependencies:
```
sudo apt update
sudo apt install mosquitto-clients
```

Then you should update the `mosquitto` config file:
```
sudo nano /etc/mosquitto/conf.d/local.conf
```

Add these lines:
```
listener 1883 0.0.0.0
allow_anonymous true
```

Restart the service for the changes to apply:
```
sudo systemctl restart mosquitto
sudo ufw allow 1883
```

Finally, run the server:
```
cargo run -p backend --release
```

### Android/Termux

Assuming you already have [termux](https://github.com/termux/termux-app) and ssh setup, install the dependencies:
```
pkg update && pkg install -y \
  nodejs-lts \
  rust \
  binutils \
  build-essential \
  sqlite \
  mosquitto \
  git \
  curl
```

Then, you should set up mosquitto config:
```
cat << 'EOF' > ~/mosquitto.conf
listener 1883 0.0.0.0
allow_anonymous true
EOF
```

Start mosquitto service at the background:
```
mosquitto -c ~/mosquitto.conf -d
```

Install `pm2` in order to run the binary as a background service:
```
npm install -g pm2
```

And finally run the server:
```
# Note: Compilation on Android is very slow, might take up to 20 minutes
cargo build -p backend --release

pm2 start ./target/release/backend --name "flowers-backend"
pm2 save
```

### SQLite note
Due to relative sqlite paths, there is a difference between `cargo run -p backend` from project root and `cargo run` here. See [#12](https://github.com/sanyaswee/flowers/issues/12)
